# PRD: PO 데일리 트레이닝 (MVP)

Oct 22, 2026 · @Seongbeom Lim

기반 기획서: Doc

## 문제 정의

PO/PM 취준생은 케이스 면접으로 프로덕트 사고력을 증명해야 하지만, 매일 연습할 소재와 즉각적인 피드백, 흩어지지 않는 기록이 없어 연습이 습관이 되지 못한다. (가설, 다이어리 스터디로 검증 예정)

- **누가**: PO/PM 직무 취업 준비생 (부트캠프 수강생, 직무 전환자 포함)
- **현재 대안**: 케이스 문제집·유튜브(일방향), 스터디(주 1\~2회), 혼자 하는 노션 역기획(지속 어려움)
- **방치하면**: 면접 직전 몰아치기 준비, 포트폴리오에 '꾸준함의 증거'를 남기지 못함

## 목표

MVP의 목표는 '브리핑 → 케이스 선택 → 답변 → 피드백 → 기록' 루프가 실제로 습관이 되는지 검증하는 것이다.

| 구분 | 목표 | 확인 방법 |
| --- | --- | --- |
| 사용자 | 매일 5분 안에 케이스 1개를 끝낼 수 있다 | 케이스 선택부터 답변 제출까지 걸린 시간 |
| 사용자 | 답변 직후 강점과 빈틈을 구체적으로 안다 | AI 피드백 '도움됨' 응답 비율 |
| 사용자 | 쌓인 기록을 면접·포트폴리오 소재로 쓸 수 있다 | 아카이브 재방문 비율 |
| 프로덕트 | 브리핑이 케이스 연습으로 이어진다 | 브리핑 조회 대비 케이스 답변 전환율 |
| 프로덕트 | 주 3일 이상 연습하는 습관이 형성된다 | 주 3일 이상 답변 유저 비율 (북극성) |

## 비목표

이번 MVP는 루프 검증에 집중하며, 아래 항목은 의도적으로 제외한다.

| 하지 않는 것 | 이유 |
| --- | --- |
| 네이티브 앱 개발 | Python·Streamlit 웹앱으로 루프 검증이 충분함 |
| 운영진 검수 없는 완전 자동 발행 | 콘텐츠 품질이 핵심 경쟁력이라 초기엔 사람이 관문 역할 |
| 채용 공고·마감 알림 | 루프 검증 전 기능 확장은 시기상조 (2단계) |
| 합격자 멘토·출제자 기능 | 유저 기반이 생긴 뒤 의미가 있음 (2단계) |
| 수익화(유료 플랜, 광고) | 포트폴리오·검증 단계이며, 일부 API의 상업적 사용 제한도 있음 |

## 사용자 스토리

페르소나는 '연습하는 취준생'과 '콘텐츠를 발행하는 운영진' 두 가지다. 우선순위 순으로 적는다.

**취준생**

1. 취준생으로서, 아침에 tech 뉴스 헤드라인과 요약 3개를 보고 싶다. 업계 흐름을 놓치지 않기 위해서다.
2. 취준생으로서, 그중 관심 가는 뉴스 하나를 골라 케이스로 연습하고 싶다. 내 관심사로 동기를 유지하기 위해서다.
3. 취준생으로서, 답변을 제출하자마자 루브릭 기준의 피드백을 받고 싶다. 내 답이 어디가 부족한지 바로 알기 위해서다.
4. 취준생으로서, 같은 케이스에 대한 다른 사람의 답변을 보고 투표하고 싶다. 다른 관점을 배우기 위해서다.
5. 취준생으로서, 내가 쓴 답변과 피드백을 날짜·유형별로 모아 보고 싶다. 면접과 포트폴리오 소재로 쓰기 위해서다.

**운영진**

6. 운영진으로서, AI가 만든 케이스 3개를 발행 전에 확인·수정하고 싶다. 잘못된 사실이나 어색한 문제가 나가지 않게 하기 위해서다.

**엣지 케이스**

- 오늘 브리핑이 아직 발행되지 않았을 때: 어제 브리핑과 발행 예정 시각을 보여준다.
- 같은 케이스에 다른 사람 답변이 없을 때: 빈 상태 안내와 함께 '첫 답변자' 메시지를 보여준다.
- AI 피드백 생성이 실패했을 때: 답변은 저장하고, 재시도 버튼을 보여준다.
- 답변이 너무 짧을 때(예: 50자 미만): 제출 전에 보완을 권한다.

## 요구사항

P0는 아침 루프(브리핑 → 선택 → 답변 → 피드백 → 기록)만 담는다. 기획서의 동료 투표와 저녁 역기획 메모는 북극성 지표(답변)에 직접 필요하지 않아 P1로 내렸다.

### P0: 없으면 출시하지 않는다

**R1. 데일리 콘텐츠 생성 배치**

매일 정해진 시각에 소재 API 3종에서 뉴스를 수집하고, LLM으로 슬롯별 헤드라인·요약·케이스·루브릭 3세트를 만들어 '검수 대기'로 저장한다.

- [ ] 슬롯 1\~3에서 각 1개씩, 총 3세트가 생성된다
- [ ] 각 세트에 원문 링크가 포함되고, 요약은 사실만 담는다 (원문 문장 복제 없음)
- [ ] 케이스 유형은 그날 요일 로테이션을 따른다
- [ ] API 호출이 실패하면 해당 슬롯만 비워 두고 운영진에게 표시한다

**R2. 운영진 검수·발행 페이지**

- [ ] 비밀번호로 보호된 관리 페이지에서 3세트를 확인·수정할 수 있다
- [ ] '발행'을 누르기 전에는 사용자에게 노출되지 않는다
- [ ] 3세트 중 일부만 발행할 수도 있다

**R3. 브리핑과 케이스 선택**

- Given 오늘 브리핑이 발행됐고, When 사용자가 홈에 들어오면, Then 헤드라인·요약 3개와 원문 링크가 보인다
- Given 브리핑 화면에서, When 하나를 고르면, Then 그 뉴스의 케이스 질문과 유형이 표시된다
- Given 오늘 브리핑이 아직 없으면, Then 어제 브리핑과 발행 예정 시각을 보여준다

**R4. 답변 작성·제출**

- [ ] 텍스트로 답변을 작성·제출할 수 있다
- [ ] 50자 미만이면 제출 전에 보완을 권한다 (제출은 막지 않음)
- [ ] 제출한 답변은 새로고침해도 사라지지 않는다

**R5. AI 피드백**

- [ ] 제출 후 해당 케이스의 루브릭 기준으로 강점·빈틈·개선 제안을 보여준다
- [ ] 사용자는 피드백에 '도움됨/아쉬움'을 표시할 수 있다
- [ ] 생성 실패 시 답변은 저장되고 재시도 버튼이 보인다

**R6. 아카이브**

- [ ] 내가 쓴 답변과 피드백을 날짜순으로 볼 수 있다
- [ ] 케이스 유형별로 걸러 볼 수 있다

**R7. 간단한 사용자 식별**

- [ ] 닉네임과 PIN으로 내 기록을 다시 불러올 수 있다

**R8. 이벤트 로깅**

- [ ] 브리핑 조회, 케이스 선택, 답변 제출, 피드백 평가가 사용자·시각과 함께 기록된다 (성공 지표 측정용)

### P1: 출시 직후 바로 붙인다

- **동료 답변 보기·투표**: 같은 케이스의 다른 답변 열람과 투표. 답변이 없으면 '첫 답변자' 안내
- **저녁 30초 역기획 메모**: 오늘 써본 서비스를 짧게 기록하고 아카이브에 함께 저장
- **카카오 로그인**: R7을 대체
- **카카오톡 아침 알림**: 브리핑 발행 시 알림 발송

### P2: 지금 만들지 않지만 설계에 고려한다

- 관심 회사 PO 공고 알림 (사람인 API 등)
- 합격자·유저 출제 구조
- 검수 없는 자동 발행 (승인 데이터 축적 후)
- 케이스 유형별 역량 분포 리포트

설계 고려: 케이스·답변·피드백 데이터를 '유형' 필드와 함께 저장해 두면 P2의 역량 리포트와 출제자 구조를 나중에 붙이기 쉽다.

### 화면 와이어프레임

P0 화면은 4개이며, 사용자의 아침 루프는 ① 홈에서 뉴스를 고르고 ②에서 답변과 피드백을 받는 두 화면 안에서 끝난다.

&#91;embedded content: 화면 와이어프레임 · P0 화면 4개\]

①\~③는 취준생용(R3\~R6), ④은 운영진용(R2)이다. 레이아웃과 문구는 논의용 초안이며 실제 구현은 Streamlit 기본 컴포넌트(버튼, 텍스트 영역, 선택 상자, expander)로 대체한다.

## 기술 구성

Python 배치 스크립트가 매일 콘텐츠를 만들어 저장하고, Streamlit 멀티페이지 앱이 이를 읽어 보여주는 두 덩어리 구조다.

&#91;embedded content: 기술 구성 · 배치, 저장소, Streamlit 앱\]

콘텐츠 생성(배치)과 사용자 화면(앱)을 분리해, 앱에서는 답변 피드백을 위한 LLM 호출만 실시간으로 일어난다.

- **언어·프레임워크**: Python, Streamlit (멀티페이지: 홈·브리핑, 케이스·답변, 아카이브, 관리자 검수)
- **외부 API**: HackerNews, 네이버 뉴스 검색, Open DART, LLM API
- **배포**: Streamlit Community Cloud (무료)
- **Streamlit 제약과 대응**
  - 예약 실행 기능이 없음 → 배치는 앱 밖에서 실행 (열린 질문)
  - 로컬 파일이 재시작 시 사라질 수 있음 → 외부 저장소 필요 (열린 질문)
  - 푸시 알림 기능이 없음 → 알림은 P1의 카카오톡 메시지로 처리
  - API 키는 코드가 아닌 Streamlit secrets에 보관

## 성공 지표

북극성은 '주 3일 이상 답변한 유저 비율'이며, 출시 2주 후 1차, 4주 후 2차로 평가한다. 목표치는 비교 데이터가 없는 초기 가설이라 1차 평가 후 조정한다.

| 구분 | 지표 | 성공 기준 | 도전 목표 | 평가 시점 |
| --- | --- | --- | --- | --- |
| 선행 | 케이스 답변 완료율 (케이스 선택 대비 제출) | 60% | 75% | 2주 |
| 선행 | 브리핑 조회 대비 케이스 답변 전환율 (가드레일) | 40% | 55% | 2주 |
| 선행 | AI 피드백 '도움됨' 비율 | 60% | 75% | 2주 |
| 선행 | 케이스 선택부터 제출까지 중앙값 시간 | 10분 이내 | 5분 이내 | 2주 |
| 후행 | 주 3일 이상 답변 유저 비율 (북극성) | 30% | 45% | 4주 |
| 후행 | D7 리텐션 | 25% | 40% | 4주 |

- **측정 방법**: R8 이벤트 로그를 집계한다. 주간 활성 유저는 '그 주에 브리핑을 1회 이상 조회한 유저'로 정의한다.

## 일정과 단계

확정된 마감일은 아직 없으며, 4단계로 나눠 각 단계 끝의 관문을 통과하면 다음으로 넘어간다.

1. **검증 준비**: 취준생 5명 대상 3일 다이어리 스터디, 블로킹 질문 4개 해결
   - 관문: 하루 중 연습하고 싶은 순간이 실제로 존재하는지 확인
2. **MVP 개발 (P0)**: R1\~R8 구현
   - 의존성: 뉴스·LLM API 키 발급, 저장소와 배치 실행 방식 결정
   - 관문: 3일 연속 브리핑이 오류 없이 발행됨
3. **클로즈드 베타 (2주)**: 부트캠프 동기 등 20명 내외로 운영, 1차 지표 평가
   - 관문: 케이스 답변 완료율 60% 이상
4. **P1 추가와 2차 평가 (4주 시점)**: 동료 투표, 역기획 메모, 카카오 로그인·알림 추가 후 북극성 평가
