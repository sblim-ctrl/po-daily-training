# PO 데일리 트레이닝 기획서

Oct 22, 2026 · @Seongbeom Lim

## 한 줄 요약

PO/PM 취준생이 하루 세 번 짧게 들어와 프로덕트 사고력을 훈련하고, 그 기록이 자연스럽게 포트폴리오로 쌓이는 AI 케이스 트레이닝 서비스.

- 아침: tech 뉴스 브리핑 3개 중 하나를 골라 5분 케이스 답변
- 점심: AI·동료 피드백 확인
- 저녁: 오늘 써본 서비스 30초 역기획 메모

## 배경 및 문제 정의

핵심 문제는 취준생의 프로덕트 연습이 '이벤트'로만 존재하고 '습관'이 되지 못한다는 것이다. (가설)

- **상황**: PO/PM 채용에서는 케이스 면접과 과제로 프로덕트 사고력을 증명해야 한다.
- **현재 대안과 한계**
  - 케이스 문제집·유튜브: 일방향이라 내 답이 맞는지 알 수 없음
  - 스터디: 주 1\~2회, 일정 맞추기가 어렵고 매일 연습은 불가
  - 노션 역기획 정리: 혼자 하다 보니 며칠 만에 끊김
- **근본 원인**: 매일 연습할 소재, 즉각적인 피드백, 흩어지지 않는 기록 세 가지가 동시에 없다.
- **방치하면**: 면접 직전에 몰아서 준비하게 되고, 포트폴리오에 '꾸준함의 증거'를 남기지 못한다.

## 타겟 유저와 JTBD

1차 타겟은 PO/PM 취준생이다. 불특정 다수는 문제 정의가 흐려지고, 현직 PO/PM은 하루를 슬랙·지라·노션 안에서 보내 별도 방문 이유를 만들기 어렵기 때문이다.

- **1차 타겟**: PO/PM 직무 취업 준비생 (부트캠프 수강생, 직무 전환자 포함)
- **확장 타겟**: 이직을 준비하는 주니어 PO/PM
- **JTBD**: 취업을 준비하는 동안 매일 조금씩 프로덕트 사고력을 연습하고 피드백을 받고 싶다. 그래서 면접에서 자신 있게 말하고 싶다.
  - 기능적 Job: 케이스 답변 연습, 피드백 받기, 포트폴리오 소재 모으기
  - 정서적 Job: '뒤처지지 않고 있다'는 확신 얻기

## 하루 사용 루프

시간대마다 서로 다른 트리거를 하나씩 배치해 하루 세 번의 방문 이유를 만든다.

&#91;embedded content: 하루 사용 루프 · 3개 트리거와 아카이브\]

아침 케이스로 시작해 점심 피드백, 저녁 기록으로 이어지고, 모든 활동이 아카이브에 쌓인 뒤 다음 날 다시 아침으로 돌아온다.

## MVP 핵심 기능

MVP는 하루 루프를 돌리는 데 꼭 필요한 5개 기능만 담는다.

| 기능 | 사용 시점 | 사용자가 얻는 것 |
| --- | --- | --- |
| 오늘의 브리핑·케이스 선택 | 아침 (푸시 알림) | tech 뉴스 헤드라인·요약 3개를 보고, 관심 가는 하나를 골라 연습 시작 |
| AI 즉시 피드백 | 답변 직후 | 내 답의 강점·빈틈 확인, 유저가 적어도 루프가 돎 |
| 동료 답변 보기·투표 | 점심 | 다른 사람의 관점 학습, 내 답에 대한 반응 |
| 30초 역기획 메모 | 저녁 | 오늘 써본 서비스를 PO 시각으로 기록 |
| 포트폴리오 아카이브 | 수시 | 쌓인 답변·메모를 모아 면접·포트폴리오 소재로 활용 |

- **이번 범위 밖**: 채용 공고·마감 알림, 합격자 멘토 매칭 (루프 검증 후 추가 검토)

## 콘텐츠 운영 방식

이 서비스의 핵심 경쟁력은 매일 새롭고 믿을 만한 케이스를 끊김 없이 공급하는 것이다. MVP는 'AI 생성 + 운영진 검수' 하이브리드로 운영한다.

**소재 구성**

- 메인: 국내외 tech·서비스 출시 뉴스를 헤드라인과 요약으로 제공하고, 뉴스마다 연습 케이스를 연결
- 보조: 공개된 면접 후기를 재구성한 기출형 케이스 (주 1\~2회)
- 초기 시드: 운영진이 직접 출제한 케이스 30개

**브리핑 슬롯 구성과 선별 기준**

선별 기준은 '이 뉴스에 프로덕트 의사결정이 담겨 있는가'이다. 기능 출시, 정책 변경, 실험, 지표 변화가 담긴 뉴스만 브리핑에 올린다.

| 슬롯 | 소재 | 연결하기 좋은 케이스 유형 |
| --- | --- | --- |
| 1 | AI·tech 서비스 출시 | 문제 정의, 역기획 |
| 2 | 국내외 서비스 기능 업데이트 | 개선안, 지표 설계 |
| 3 | 그로스·비즈니스 의사결정 (프로덕트 관점이 있는 기획·마케팅 뉴스) | 지표 설계, 우선순위 |

- **제외**: 순수 광고·브랜드 캠페인, '오늘의 뉴스'가 아닌 기획 방법론 아티클

**제작 흐름**

1. tech 뉴스·후기에서 소재를 수집해 헤드라인·요약 3개 작성 (사실만 요약, 원문 복제 금지)
2. AI가 뉴스 3개 각각에 대해 문제 초안과 평가 루브릭을 함께 생성 (루브릭이 AI 피드백 품질의 기준)
3. 운영진이 케이스 3개를 검수 후 발행
4. 아침 푸시로 브리핑 발행, 사용자가 하나를 골라 케이스로 연습

**요일별 유형 로테이션**

| 요일 | 유형 | 질문 예시 |
| --- | --- | --- |
| 월 | 문제 정의 | 이 기능은 어떤 사용자 문제를 풀려는 걸까? |
| 화 | 지표 설계 | 이 기능의 성공 지표를 무엇으로 잡겠는가? |
| 수 | 우선순위 | 후보 기능 3개 중 무엇을 먼저 하겠는가? |
| 목 | 개선안 | 이 서비스의 가장 큰 불편 하나와 개선안은? |
| 금 | 역기획 | 이 기능이 나온 배경과 의사결정을 추론한다면? |

- 유형을 고정하면 문제가 단조로워지지 않고, 아카이브에서 유형별 역량 분포를 보여줄 수 있다.
- **2단계 확장**: 합격자·유저가 직접 출제하는 구조로 전환해 콘텐츠 공급 병목과 '합격 후 이탈' 문제를 함께 푼다.

## 활용 API (MVP)

MVP는 소재 3개, 운영 2개, LLM 1개 총 6개 API로 하루 루프 전체를 구성하며, 비용은 LLM에서만 발생한다.

| 용도 | API | 비고 |
| --- | --- | --- |
| 슬롯 1 소재: AI·tech | HackerNews API | 인증 불필요 |
| 슬롯 2 소재: 서비스 업데이트 | 네이버 검색 API (뉴스) | 하루 호출 한도 내 무료 |
| 슬롯 3 소재: 그로스·비즈니스 | Open DART | 공시·재무 숫자를 지표 설계 케이스 근거로 활용 |
| 로그인 | 카카오 로그인 |  |
| 아침 푸시 | 카카오톡 메시지 | 앱 없이 MVP 배포 가능 |
| 문제·루브릭 생성, AI 피드백 | LLM API | 유일한 유료 항목 |

- 무료 조건과 상업적 사용 가능 여부는 구현 전 각 공식 약관에서 확인한다.

## 성공 지표

북극성 지표는 '주 3일 이상 케이스에 답변한 유저 비율'이다. 하루 3회 방문은 최종 목표지만, 초기에는 루프가 습관으로 자리 잡는지부터 확인한다.

- **북극성**: 주간 활성 유저 중 주 3일 이상 답변한 유저 비율
- **보조 지표**
  - 1인당 일 평균 방문 수 (최종 목표 3회)
  - 아침 케이스 답변 완료율
  - AI 피드백 '도움됨' 응답 비율
  - D7 리텐션
- **가드레일**: 브리핑 조회 대비 케이스 답변 전환율 (브리핑만 읽고 이탈하는지 확인)

## 리스크와 검증 계획

가장 위험한 가정은 '취준생의 하루에 들어올 이유가 3번 존재한다'는 것이다. 이게 틀리면 빈도 목표 자체를 다시 정해야 한다.

| 핵심 가정·리스크 | 틀리면 생기는 일 | 가장 싼 검증 방법 |
| --- | --- | --- |
| 하루에 자연스러운 방문 순간이 3번 있다 | 빈도 목표 재설정 필요 | 취준생 5명 대상 3일 다이어리 스터디 |
| AI 피드백이 충분히 유용하다 | 답변 후 재방문 동기 약화 | 케이스 10개로 AI 피드백 품질 블라인드 평가 |
| 합격하면 이탈한다 (성공할수록 이탈) | 리텐션 상한이 생김 | 합격자를 출제자·멘토로 전환하는 구조 검토 |
| 타겟 시장이 작다 | 성장 한계 | 주니어 PO/PM 대상 확장 가능성 인터뷰 |
